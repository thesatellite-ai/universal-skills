# CLAUDE.md — universal-skills

## Project memory

**Project memory lives in `.ai/memory/`.** Read `.ai/memory/INDEX.md` at session start. Before editing any file, grep `.ai/memory/FILES.md` for that path (and its parent dir) and read the chunks it names — that is where this repo's non-obvious decisions, gotchas, and rejected alternatives are recorded. Capture new ones with the `satl-project-memory` skill or the `project-memory` CLI. Chunks are immutable: correct one by writing a new chunk with `supersedes:` and flipping the old one's `status:` to `superseded`.

## What this project is

A published, open-source library of **agent skills** — self-contained instruction modules that extend AI coding agents (Claude Code, Cursor, Codex, Copilot, Windsurf, Gemini, Cline). Each skill is a directory containing a `SKILL.md`: YAML frontmatter (`name`, `description`) plus markdown instructions the agent loads on demand when the description matches what the user is doing.

There is **no application here and no build step**. The deliverable is markdown. A few skills ship an optional bash helper alongside their `SKILL.md`, but the repo has no compiler, no package manifest, no dependency tree, and no CI. Distribution is via the `skills` CLI from skills.sh (`npx skills add thesatellite-ai/universal-skills`) and via `Taskfile.yml` symlink installs for local development.

Every skill is namespaced `satl-` so the collection can grow without colliding with other libraries.

## Build and test

There is no build. Commands that exist:

```bash
task --list          # every task, self-documenting
task list            # every skill dir in the repo (dirs containing SKILL.md)
task install         # symlink all satl-*/ into ~/.claude/skills (live — edits apply immediately)
task install-copy    # same, but snapshot copies instead of symlinks
task install-remote  # install from GitHub via `npx skills add`
task uninstall       # remove all satl-* from ~/.claude/skills
```

`SKILLS_DIR` overrides the install target (default `~/.claude/skills`).

Only skills that ship executables have tests, and they live in the skill's own directory:

```bash
task check           # everything CI runs: lint + both suites
task lint            # structural checks only (bash lint-skills.sh)
task test            # both suites only

bash satl-project-memory/test.sh     # 41 tests; or: cd satl-project-memory && task test
bash satl-agent-messaging/test.sh    # 181 tests; or: cd satl-agent-messaging && task test
```

Both suites run in an isolated `mktemp -d` tree and never touch real state. `.github/workflows/test.yml` runs the lint plus both suites on push and PR, on **ubuntu-latest and macos-latest** — the macOS runner matters because it ships bash 3.2, so the scripts must avoid bash 4+ features (`mapfile`, `${var,,}`, associative arrays). Run the suite of any skill whose script you touch.

## Project structure

```
satl-<name>/            one skill each — SKILL.md (required) + README.md (convention)
  SKILL.md              frontmatter + instructions; this is the actual product
  README.md             why the skill exists, for humans browsing GitHub
  <executable>          optional bash helper, no extension, chmod +x
  test.sh               optional behavioral suite for that helper
  Taskfile.yml          optional per-skill tasks (test/demo/etc.)
  templates/ EXAMPLES/  optional supporting assets (satl-brand-kit, satl-replay-checklist)
brand/                  visual identity — brand.json manifest, gen-brand.mjs, SVGs, png/, tokens
lint-skills.sh          structural lint for every satl-*/ (frontmatter, README table, tests)
.github/workflows/      test.yml — lint + both suites on ubuntu and macos

docsi/                  SYMLINK, gitignored — repolink-managed, points into a private repo
.ai/memory/             project memory store (see top of this file)
README.md               the public landing page — skills table, badges, FAQ, SEO copy
Taskfile.yml            repo-level install/uninstall tasks
skills-lock.json        UNTRACKED and gitignored — generated by the skills CLI
```

Two entries above are not part of the repo's committed content and are easy to trip over. **`docsi/` is a symlink** managed by the `repolink` tool into `private-repo/skills-ai/universal-skills/docsi` — it is absent on a fresh clone, and writing into it writes into a different, private repository. **`skills-lock.json` is gitignored and untracked**, so it exists only on machines that have run the `skills` CLI; never hand-edit it (see the memory chunk on its hash format).

`.claude/settings.local.json` is likewise gitignored — machine-local hook config that must never be committed to this public repo.

Skills are flat and self-contained. There is no shared library, no cross-skill import, and no build that assembles them.

## How a skill works

```
user says something
  -> agent matches it against every installed SKILL.md `description`
  -> loads that SKILL.md into context
  -> follows its instructions for the rest of the task
```

The `description` field is therefore the most important line in a skill: it is the entire trigger surface. It must enumerate the literal phrases a user would say ("rewrite my homepage", "fix the favicon", "harvest this chat"), not describe the skill abstractly. A skill with a vague description never fires.

`name` must equal the directory name, and both carry the `satl-` prefix.

## Adding a skill

1. `mkdir satl-<name>/`, write `SKILL.md` (frontmatter `name` = dir name) and `README.md`.
2. Add a row to the **All skills** table in the root `README.md`, and bump the skill-count badge on line 11.
3. If it ships an executable: name it the skill name **minus the `satl-` prefix** (`satl-project-memory` ships `project-memory`), `chmod +x`, and write a `test.sh`.
4. `task install` to symlink it, then restart the agent session — the skill list is built at session start.
5. Leave `skills-lock.json` alone.

## What's implemented

- 21 skills, each with `SKILL.md` + `README.md`.
- Two shipped executables with test suites: `satl-project-memory/project-memory` (41 tests), `satl-agent-messaging/agentmsg` (181 tests) — the latter covering rooms, identities with roles, direct + `--all`/`--role` broadcast, read/peek/archive/history, `leave`/`rmroom`, and a blocking `watch` service with a pidfile registry (`unwatch`, `watchers`).
- Full brand kit in `brand/`, regenerable via `brand/gen-brand.mjs` and `brand/Taskfile.yml`.
- Repo-level install/uninstall tasks, symlink and copy modes.
- A populated project memory store in `.ai/memory/`.

## What's NOT implemented

Assume none of the following exist:

- **No pre-commit hooks.** CI runs on push/PR (see below), but nothing stops a bad commit locally. Run `task check` yourself.
- **No code formatter, and no shellcheck.** `lint-skills.sh` checks skill *structure*, not shell style. There is no prettier, markdownlint, or editorconfig enforcement, and no "make it pass lint" step for the markdown prose itself.
- **No package manifest.** No `package.json`, no `go.mod`. `npx skills` is invoked directly by a task.
- **Markdown *content* is still unvalidated.** The lint checks frontmatter, `name`-matches-directory, README-table presence, and that an executable ships a `test.sh`. It does not catch a broken cross-skill reference, a dead link, a stale example, or prose that contradicts the code.
- **No `LICENSE`, `CONTRIBUTING.md`, `CHANGELOG.md`, or `SECURITY.md`** at the repo root, and no issue/PR templates under `.github/` — despite `satl-oss-scaffold` being the skill that generates exactly those files for other repos. `.github/` currently holds only the test workflow.
- **No versioning or releases.** No tags, no changelog, no semver. `main` is the product.
- **`skills-lock.json` is stale and partial** — it lists 13 of 21 skills. It is generated by the `skills` CLI and lags the repo.
- **Most skills ship no executable.** Only two do. Do not assume a skill has a CLI or tests.

## Conventions

- **Never hard-wrap markdown.** Every prose paragraph, bullet, and table cell is one continuous physical line. Only fenced code, YAML frontmatter, and table rows break. This is enforced across every `.md` in the repo.
- **`README.md` is public-facing and plain markdown** — GitHub-rendered, SEO-tuned, no component grammar. Skills that write internal docs (`.ai/**`, `PLAN.md`, `*_ADR.md`) use filemark grammar instead, via `satl-filemark-docs`.
- **A skill's `README.md` explains *why the skill exists*** — the problem it solves and how it differs from neighbours — not how to use it. Usage lives in `SKILL.md`.
- **Skill instructions are written in the second person to the agent** ("Your job is…", "Do not…"), not as documentation about the skill.
- **Executables have no file extension** and are invoked by name, not `bash foo.sh`.
- **Bash scripts use `set -euo pipefail`.** Note the trap recorded in memory chunk `2026-08-07-01`: `test && cmd` as the final statement of a loop body aborts the script under `set -e`. Use `if` blocks.
- **Cross-skill references are by name in prose only.** A skill never reads or imports another skill's files.
- **Commit messages** are mixed in history — some conventional (`feat(skill):`, `docs(skills):`), some plain (`Add satl-agent-messaging skill: …`). Prefer the conventional form for new commits. Never mention Claude, AI, or Anthropic; no `Co-Authored-By` lines.
