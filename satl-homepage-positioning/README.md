# satl-homepage-positioning — purpose & use case

## Why this skill exists

Almost every weak homepage fails the same way — **broad + vague + feature-dump** — so a cold visitor can't tell what it is, who it's for, why it's different, or why to act now, and they leave. Founders rewrite the hero by instinct and make it cleverer, not clearer. The fix is a repeatable method, not taste.

`satl-homepage-positioning` encodes the Fletch PMM positioning method (Anthony Pierri / Brendan Hufford), distilled from ~18 of their public before/after homepage teardowns plus their published framework, so any page can be diagnosed and rewritten against a fixed rubric.

## What it does

Runs a discovery Q&A, then diagnoses and rewrites the page toward one shape:

> **One audience · one wedge use case · an explicit named problem · a category anchor with a point of view · capabilities that make the benefit believable.**

It checks the page answers the **5 questions** a visitor should resolve in ~10 seconds (what does it do, how does it work, what does it look like, when would I use it, how does it help me make progress), specifies what the hero must contain (category anchor, one primary audience, one wedge use case, differentiation vs a *named* alternative, a point of view), and produces a diagnosis, new hero copy options, a section-by-section spec, and before→after annotations.

It defaults to **clear over clever** every time.

## When to use it

- "Rewrite / critique / improve my homepage, landing page, or hero."
- "It isn't converting" / "too vague" / "too broad" / "feature-heavy."
- Launching a product and need the landing copy + structure, or want "positioning" / "messaging" / "value proposition" / a "before/after."

## NOT for

- Pure visual/UI design (use a frontend skill), an interactive pitch *deck* (use `satl-frontend-pitch`), in-app UI microcopy, or blog/SEO article drafting.
